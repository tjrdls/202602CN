# NetCare 발표 자료 (기술 설명)

> 슬라이드 한 장 = `##` 한 개 기준으로 구성했습니다. 발표 시간 약 12~15분.

---

## 1. 표지
**NetCare** — 초보자 친화형 실시간 네트워크 패킷 분석 및 자동 문제 해결 시스템
"Wireshark의 분석력 + 토스의 쉬움 + 스스로 고치는 네트워크 도우미"

## 2. 문제 정의
- Wireshark는 강력하지만, 초보자는 `TCP SYN`, `RST`, `TTL` 같은 용어와 수천 줄의 목록 앞에서 멈춥니다.
- 기존 모니터링 도구는 "경고"만 하고 **무엇을 해야 하는지** 알려주지 않습니다.
- 목표: **탐지 → 원인 → 쉬운 설명 → 해결 방법 → 승인 후 조치 → 검증 → 되돌리기**

## 3. 핵심 기능 6가지
1. 실시간 패킷 수집 (Scapy, BPF 필터)
2. 계층별 헤더 분석 (Ethernet → IP → TCP/UDP → 응용)
3. 실제 데이터 기반 통계
4. 실시간 그래프 (1초 갱신)
5. 이상 탐지 (규칙 + 통계)
6. 진단과 승인 기반 자동 해결 (롤백 포함)

## 4. 시스템 아키텍처
```
캡처 스레드 ─▶ 제한 큐 ─▶ 처리 스레드 ─┬▶ 실시간 통계
 (Scapy)     (5만, 넘치면 버리고 집계)  ├▶ 탐지기 ─▶ 진단기 ─▶ 이상 징후 DB
                                       └▶ SQLite (WAL, 보존 한도)
점검 스레드(ping·DNS) ─▶ 종합 점수        조치 관리자(승인·검증·롤백)
FastAPI (127.0.0.1) ◀── 1초 폴링 ── 브라우저 UI (HTML/CSS/JS)
```
- **캡처와 UI를 분리:** 캡처 콜백은 큐에 넣기만 하고, 파싱·탐지·저장은 별도 스레드가 배치로 처리합니다.
- **기술 선택:** Streamlit은 스크립트 전체를 다시 실행하는 구조라 백그라운드 캡처와 토스 스타일 UI를 구현하기 어렵습니다. 그래서 FastAPI와 빌드가 필요 없는 정적 UI를 선택했습니다.

## 5. 네트워크 원리 ① — 3-way handshake로 SYN Flood 구분하기
```
정상:   A ──SYN──▶ B   A ◀─SYN-ACK── B   A ──ACK──▶ B   (완료)
Flood:  A ──SYN──▶ B   A ◀─SYN-ACK── B   (마지막 ACK 없음)
```
- 단순히 SYN 개수만 세면 브라우저가 연결을 많이 여는 정상 상황도 탐지됩니다.
- SYN-ACK "응답률"로 판정하면, 피해 서버는 응답을 보내므로 공격을 놓칩니다.
- **NetCare는 연결을 시작한 쪽의 마지막 ACK까지 추적해 "연결 완료율"로 판정합니다.** 완료율이 30% 미만일 때만 경고합니다.

## 6. 네트워크 원리 ② — 오탐을 줄이는 방법
| 상황 | 단순 규칙 | NetCare |
|---|---|---|
| 대용량 다운로드 | "과다 패킷 위험" | 역방향 ACK 비율로 양방향 통신 판정 → 등급을 낮춤 (TCP 지연 ACK로 실측 0.19 → 기준 5%) |
| A/AAAA 동시 질의 중 AAAA만 무응답 | "DNS 실패 위험" | 같은 도메인의 A가 성공하면 사용자 영향 없음 → 제외 |
| 정상 API 폴링 | "반복 연결" | 핸드셰이크가 완료되면 정상 |
| HTTPS 443에 트래픽 집중 | "포트 집중" | 일반 서비스 포트 → 정보 등급 |
- 표현 원칙: "공격"이라고 단정하지 않고 "이상 징후"라고 하며, **오탐 가능성을 함께 설명**합니다.

## 7. 네트워크 원리 ③ — 통계적 이상 탐지
- 초당 바이트를 EWMA(지수가중이동평균)로 평균·분산을 학습합니다 (α=0.05).
- `z = (현재 - 평균) / 표준편차 ≥ 4` **그리고** 1MB/s 이상이면 급증으로 판정합니다.
- 60초 학습 전에는 고정 임계값을 쓰고, 이상 구간은 기준선 학습에서 뺍니다(기준선 오염 방지).
- 실측: 평상시 학습 66초 → 다운로드 시작 → **z-score 7.51로 탐지**, 평상시 오탐 0건

## 8. 네트워크 원리 ④ — 캡처와 방화벽의 순서
- 패킷 캡처(BPF/Npcap)는 방화벽보다 **먼저** 일어납니다.
- 그래서 IP를 차단해도 **들어오는** 패킷은 캡처에 계속 보입니다(방화벽이 그 뒤에 버림).
- 차단 효과는 "**내가 그 IP로 보내는 패킷이 0인가**"로 검증하고, 이 원리를 화면에서도 설명합니다.

## 9. HTTPS를 정직하게 다루기
- TLS 본문은 암호화되어 있어 **복호화 없이 볼 수 없습니다**. NetCare는 복호화하지 않습니다.
- 보이는 것은 평문 메타데이터뿐입니다: TLS 레코드 종류, ClientHello의 **SNI(접속 도메인)**.
- 화면 문구도 "핸드셰이크(일부 평문)"와 "Application Data(암호화)"로 구분했습니다.

## 10. 초보자 UX (토스 스타일)
- 흰/연회색 카드, 초록 포인트 색, 정상(초록)·주의(주황)·위험(빨강)
- 전문 용어를 생활 언어로 바꿈: `TCP SYN 증가` → "새로운 연결 요청이 많아졌어요", `Destination IP` → "데이터를 받는 장치", `Port 443` → "HTTPS 웹 통신(암호화)"
- 장치 이름: "내 컴퓨터", "같은 네트워크의 장치", 도메인(DNS 응답으로 학습)
- 전문가 모드: 원본 필드 이름, 헥사 덤프, 실행 명령
- 반응형 (모바일에서는 하단 탭 바)

## 11. 종합 상태 점수 — 근거 없는 점수는 없다
- 100점에서 **실측한 문제만** 감점: 이상 징후(위험 25, 주의 10, 정보 2), 공유기·인터넷 ping 손실·지연, DNS 실패
- 측정하지 않은 항목은 "측정 대기"로 표시하고 감점하지 않습니다.
- "왜 이 점수인가요?"에서 감점 내역을 그대로 공개합니다.

## 12. 진단 → 승인 → 조치 → 검증 → 롤백
1. 원인 분석: 무엇이 / 누가 / 어떤 프로토콜로 / 왜 / 어떤 영향이
2. 문제와 관련 있는 조치만 추천: 예) DNS 실패 → DNS 테스트, 캐시 초기화, 연결 점검
3. 승인 모달: 할 일, 부작용, 실행 명령, 관리자 권한, "이해했어요" 체크
4. 실행 → 결과 → 효과 검증 → 되돌리기 (pf 토큰 반납으로 원래 상태 복원)

## 13. 안전장치
- 자동 차단은 기본으로 꺼져 있고, 켤 때 동의가 필요합니다(API에서도 검사). 엄격한 조건과 30분 자동 해제
- 보호 IP(내 IP, 게이트웨이, DNS 서버, 특수 주소, 화이트리스트)는 차단을 거부합니다.
- NetCare 전용 규칙만 수정합니다 (pf anchor / iptables comment / netsh 이름)
- 테스트 데이터에서 나온 징후로는 시뮬레이션만 합니다.
- 로컬 API 보호: 127.0.0.1에만 바인딩, Host 검사, 커스텀 헤더(CSRF 방지)
- 관리자 권한이 없으면 직접 실행할 명령을 안내하고, macOS에서는 OS 암호 창으로 실행할 수 있습니다.

## 14. 데모 시나리오 (약 4분)
1. 캡처 시작 → 홈: 점수, 실시간 그래프, 많이 통신한 장치(도메인 표시)
2. 패킷 분석 → HTTPS 패킷 클릭 → 계층 트리, SNI, "암호화되어 볼 수 없음"
3. 테스트 데이터 "SYN Flood" 재생 → 점수 하락, 문제 해결에 "새로운 연결 요청이 평소보다 많아졌어요"
4. 판단 근거 게이지(기준 60 / 측정 2,501, 완료율 0%) → 오탐 가능성 → 통신 내역 확인 실행
5. 차단 검토 → 승인 모달 → 시뮬레이션 실행 → 되돌리기
6. 리포트 → PDF 저장

## 15. 테스트 결과
- pytest **34/34**, UI E2E **29/29** (JS 오류 0)
- 실제 네트워크: 평상시 66초 오탐 0건, 다운로드 급증 z=7.51 탐지, 정상 다운로드는 "위험"이 아님
- 루프백 실험: 포트 스캔·반복 연결·UDP 폭주 탐지
- **실험으로 찾아 고친 오탐/버그 8건** (DNS AAAA, 반복 연결, 지연 ACK, 처리 지연 시계 등)

## 16. 한계와 향후 과제
- 관리자 권한 환경에서 pf 실제 차단 검증, Linux/Windows 실기기 검증
- Python 처리 성능 한계 → 필요하면 캡처 단계를 C 확장/eBPF로 교체
- 장치별·시간대별 기준선(현재는 전체 트래픽 기준선 하나)
- 선택적 AI 설명(환경변수 키, 규칙 기반 결과를 요약하는 보조 역할)
