# NetCare 고도화·리디자인 — 1단계 분석 결과와 개선 계획

- 작성일: 2026-11-15
- 범위: 사용자 요청 "전체 프로젝트 고도화 및 프리미엄 UI/UX 리디자인" 중 **1단계(분석·계획)**. 코드는 아직 바꾸지 않았음.
- 유지할 원칙(이전 승인 사항): 실제 캡처 데이터와 실험실 데이터 완전 분리, 실험실·테스트 데이터로는 실제 방화벽·시스템 변경 금지, 확정할 수 없는 탐지는 '의심' 표기, 합성 데이터 지표는 "합성 데이터 기준" 명시, 기존 기능·테스트 데이터 5종 유지, 단계마다 테스트·실패·수정·한계 보고.

## 1. 현재 구조 분석

### 1-1. 규모
| 영역 | 파일 | 규모 |
|---|---|---|
| 백엔드(Python) | `netcare/` 24개 모듈 | 약 5,700줄. 가장 큰 파일: detector 532, engine 522, advanced 509, explainer 478, server 471, actions 464 |
| 프론트엔드 | `web/app.js` 1개, `app.css` 1개, `index.html` 1개 | 137KB (app.js 95KB 단일 파일, 함수 70여 개, 전역 상태 객체 `S` 하나, `innerHTML` 템플릿 36곳) |
| API | FastAPI | 43개 엔드포인트 (일반 27 + 실험실 16) |
| DB | SQLite WAL | 실제: sessions, packets, traffic_minute, anomalies, actions, health_history, ip_names / 실험실: experiments, benchmarks (별도 파일) |
| 테스트 | pytest 55 + 브라우저 E2E 42 항목 | 다크 모드·반응형·성능 검사는 없음 |

### 1-2. 데이터 흐름 (현재)
```
[캡처 스레드] Scapy ─▶ 제한 큐(5만) ─▶ [처리 스레드] 파서 → 통계 → 탐지기(기본 9 + 확장 8 + EWMA) → 진단기 → DB 배치 저장
[점검 스레드] ping·DNS ─▶ health_history ─▶ 상태 점수
[FastAPI] /api/* ◀── 브라우저가 1초마다 폴링 (home: dashboard / 그 외: status + 화면별 데이터)
[실험실] 별도 Engine + simlab.db, put_sync 로 인과적 주입, 가상 조치만 적용
```
- 캡처와 UI는 이미 분리되어 있고(큐·배치), 종료 시 `shutdown()`이 있음. 구조 자체는 유지할 가치가 있음.

### 1-3. 발견한 문제점

**디자인 시스템**
1. CSS 토큰이 21개(색 16, 반경 2, 그림자 1, 폰트 2)뿐이고 **간격·글자 크기·굵기·z-index 척도가 없음** → 화면마다 px 값이 제각각.
2. **다크 모드 없음.** 차트 색은 JS `COLORS` 상수에 하드코딩되어 있어 테마와 분리되지 않음.
3. 버튼·카드·배지·표·모달이 화면별 클래스(`.lab-*`, `.s-sim`, `.ba`, `.tl`)로 따로 자라서 **동일 요소가 화면마다 미묘하게 다름.**
4. 빈 상태·로딩·오류 상태 디자인이 일부 화면(홈 안내문)에만 있음.

**홈**
5. 핵심 지표 6개와 점수는 있으나 "최근 탐지 이벤트"와 "최근 연결 IP"가 활동 로그와 섞여 있음. 점수 근거는 이미 공개(접기/펼치기) — 유지.
6. 1초 폴링마다 대시보드 전체 JSON을 받아 Plotly를 다시 그림(`Plotly.react` 1곳). 패킷 수가 많아도 동작하지만, 탭 전환 시 깜빡임과 CPU 사용이 있음.

**패킷 분석**
7. 서버 필터가 `proto`와 자유 검색 `q`뿐. **IP·포트별 필터, 정렬, 페이지 처리 없음**(위로 스크롤해 "이전 패킷" 로드만 가능). `q`는 7개 컬럼 LIKE라 패킷이 많으면 느림.
8. 상세는 오른쪽 드로어만 있음. 계층 트리·헥사 덤프·쉬운 설명은 이미 구현됨 — 유지.
9. HTTPS 본문에 대한 표현은 이미 정직함("암호화되어 볼 수 없음") — 유지하고 재확인만.

**문제 해결**
10. 요청한 9단계 중 **"정상 상황과의 차이"**, **"언제 발생(시작~최근, 지속 시간)"**, **"조치 이후 개선 여부"가 한 화면의 타임라인으로 연결되어 있지 않음.** 데이터는 있음(anomalies.first_seen/last_seen, actions.verification) → 표현 문제.
11. 탐지 규칙의 조건·임계값·오탐 가능성·한계가 설명문 안에 산재해 있고, **규칙 카탈로그로 구조화되어 있지 않음.**

**리포트**
12. 위험 수준별 집계, 탐지→대응 결과 요약, **실험실 평가 결과 포함이 없음.** 실제/테스트 구분은 이미 있음(`include_test`).
13. PDF 한글 폰트는 OS 폰트 경로 탐색에 의존 — macOS·Windows는 되지만 글꼴 없는 Linux에서는 깨질 수 있음.

**실험실**
14. 일시정지 없음, 실행 전 "예상 결과" 안내 없음, 카드에 난이도·실험 목적 없음. 지표·재현(시드)·합성 데이터 표기·분리는 완료.

**탐지**
15. 규칙 17종. 요청 목록 중 **"비정상 패킷 크기"와 "비정상 프로토콜 비율"은 없음.** 둘 다 기준선 대비 편차로 탐지 가능하지만 오탐 위험이 커서 '정보' 등급 + 실측 검증 후에만 추가해야 함.
16. "비정상 DNS 응답"은 dns_spoof_suspect(응답 충돌·서버 불일치)로 일부만 커버. NXDOMAIN 폭주·비정상 TTL은 미구현.

**안정성·성능**
17. `_prune`이 배치 삽입마다 COUNT(*) 를 실행 → 패킷 30만 건 근처에서 삽입 지연 가능. 주기적 정리로 바꿔야 함.
18. `engine.names`(도메인 학습), 탐지기의 피어별 버킷 등 **장시간 실행 시 자라는 딕셔너리의 상한이 일부 없음** → 24시간 실행 메모리 측정 필요.
19. 종료 시 프로브 스레드·DB 연결 정리는 있으나 **테스트로 검증된 적 없음.**

**코드 품질**
20. app.js 단일 파일 95KB. 빌드 도구 없이도 **ES 모듈로 분리**(state / api / components / views별) 가능하고, 그래야 리디자인 중 회귀를 막을 수 있음.

## 2. 개선 계획 (효과 큰 순서)

### 2단계. 디자인 시스템 (토큰 → 컴포넌트)
- `tokens.css`: 의미 기반 색(primary / normal / warning / critical / info / surface / border / text-1·2·3), 간격 4px 척도, 글자 크기 6단계, 굵기 3단계, 반경·그림자·z-index. **라이트/다크 2세트**, OS 설정 자동 + 수동 전환(저장).
- `components.css`: 버튼 4종(primary/secondary/ghost/danger) × 3크기, 카드(헤더·본문·푸터), 표(정렬 헤더·고정 헤더·행 선택), 배지(위험도·출처), 칩, 모달·드로어, 토스트, 탭/세그먼트, 빈 상태·로딩 스켈레톤·오류 블록, 폼 요소.
- 차트 테마: Plotly 레이아웃·색을 토큰에서 읽는 함수 하나로 통일(라이트/다크 자동).
- app.js를 ES 모듈로 분리(기능 변화 없이). E2E 42항목으로 회귀 확인.
- **산출물:** 컴포넌트 미리보기 페이지(`/static/ui-kit.html`, 개발용) + 스크린샷.

### 3단계. 화면 리디자인 (홈 → 패킷 → 문제 해결 → 리포트 → 실험실)
| 화면 | 바꾸는 것 | 유지하는 것 |
|---|---|---|
| 홈 | 상단 KPI 행(상태·점수·다운/업·PPS·총 패킷·이상 건수), 사용량 그래프 부드러운 갱신(데이터만 교체), "최근 탐지 이벤트" 카드와 "최근 연결·주요 통신" 카드 분리, 데이터 없음 → 대기 상태 | 점수 근거 공개, 실측 없으면 감점 안 함 |
| 패킷 분석 | 컬럼 추가(출발·목적 포트, 플래그, 크기), 컬럼 정렬, 페이지/가상 스크롤, IP·포트·프로토콜 필터 바(서버 측 필터 + 인덱스), 상세를 오른쪽 패널로 고정(넓은 화면)/하단(좁은 화면) | 계층 트리, 헥사, 쉬운 설명, HTTPS 정직 표기 |
| 문제 해결 | 9단계 구조로 상세 재배치, **발생→탐지→조치→검증 타임라인**, "정상 기준 vs 측정값" 비교 블록, 규칙 카탈로그 링크 | 승인 모달·롤백·오탐 가능성 |
| 리포트 | 위험 수준별 이벤트, 탐지·대응 결과 표, 실험실 평가 요약(합성 데이터 배지), 기간 프리셋, PDF 레이아웃 정리·폰트 번들 검토 | 실제/테스트 구분, CSV 5종 |
| 실험실 | 카드에 목적·난이도·예상 결과, 일시정지, 진행 단계 표시, 결과 자동 요약 문장 | 분리·재현성·합성 데이터 표기 |
| 공통 | 전역 검색(IP·포트·도메인·이벤트), IP 상세 팝업(통신량·연결 포트·이름·관련 이벤트), 최근 탐지 기록, 키보드 단축키(1~5 탭, `/` 검색, `Esc`), 모바일 하단 탭 | 전문가 모드 토글 |

### 4단계. 기능 고도화
- **규칙 카탈로그 API** `/api/rules`: 규칙별 조건·임계값(현재 설정값 반영)·근거·위험 수준·오탐 가능성·적용 환경·한계. 전문가 모드와 문제 해결 상세에서 표시.
- 신규 규칙 후보(각각 실제 캡처로 오탐 측정 후 채택 여부 결정):
  - 프로토콜 비율 이상(기준선 대비 UDP/ICMP 비율 급변) — '정보'
  - 비정상 패킷 크기(동일 피어의 크기 분포 급변·최대 크기 초과) — '정보'
  - DNS 응답 이상(NXDOMAIN 비율 급증, 비정상 TTL) — '주의' 이하
- 탐지 설명문에 "정상과의 차이" 수치 추가(기준선 평균·표준편차 대비).
- 실험실: 일시정지, 예상 결과(시나리오별 기대 탐지 유형·소요 시간 범위, 과거 벤치마크 기반).
- 안정성: 주기적 프루닝, 자라는 딕셔너리 상한, 종료 정리 테스트, 2시간 이상 실행 메모리 측정(24시간은 사용자 환경에서 별도 측정 제안).

### 5단계. 통합 테스트
- pytest 전체 + 신규(규칙 카탈로그, 필터·페이지 API, 프루닝, 종료 정리).
- E2E: 기존 42 + 다크 모드, 반응형 3폭(1280/860/390), 패킷 필터·정렬, 타임라인, 전역 검색, 실험실 일시정지.
- 실측: en5 실시간 캡처(평상시·다운로드), pcap 가져오기, 테스트 데이터 5종, 실험실 벤치마크 재실행(지표 변화 비교), CSV/PDF 출력 확인, 데이터 분리 재확인.

## 3. 결정이 필요한 항목
1. **주 색상**: 현재는 초록이 브랜드와 '정상' 상태를 겸함. 제안 — 주 색상을 청록·파랑 계열로 옮기고 초록은 '정상' 상태 전용으로 남겨 색의 의미를 분리. (기존 발표 자료와 색이 달라짐)
2. **다크 모드 전환 방식**: OS 설정 자동 + 상단 토글(저장) 제안.
3. **추가 편의 기능 범위**: 전역 검색·IP 상세 팝업·최근 탐지 기록·키보드 단축키·빈/로딩/오류 상태는 포함 제안. **즐겨찾기 IP·알림 설정**은 저장 구조와 설정 화면이 더 필요해 후순위(요청 시 포함).
4. **진행 방식**: 2~5단계를 하나씩 끝낼 때마다 보고하고 다음 단계로 진행. 중간에 UI가 바뀌는 동안 8765 서버는 사용자가 띄운 그대로 두고, 별도 포트·데이터 폴더에서 작업.

## 4단계 결과 — 기능 고도화
- **규칙 카탈로그** `detection/rules.py` + `/api/rules`: 22종 각각 탐지 조건(현재 설정값 반영)·임계값·근거·위험 수준·오탐 가능성·적용 환경·한계. 화면: 문제 해결의 "탐지 규칙 보기", 상세의 "규칙 설명", 전역 검색.
- **신규 규칙 3종 (모두 '정보' 등급 · '의심')**: 비정상 패킷 크기(대형 ICMP/DNS), 프로토콜 비율 이상(60초 학습 후 평소 대비 50%p↑, 100PPS 이상일 때만), 존재하지 않는 도메인 조회 급증(NXDOMAIN 20건·도메인 10개 이상).
  - 검증: 단위 테스트(탐지·미탐 경계), 기존 테스트 데이터 5종과 실험실 정상 기준선에서 오탐 0, 실제 네트워크(en5, 절전 구간 포함 약 31분·42,559패킷)에서 3종 모두 0건.
  - 한계: 실제 공격 트래픽으로는 검증하지 못함(합성 레코드 기준). 그래서 등급을 '정보'로 고정.
- **실측으로 찾은 오탐 1건 수정**: macOS의 DNS-SD 탐색(`…_dns-sd._udp.x.in-addr.arpa`)과 역방향 조회는 NXDOMAIN이 정상인데 "DNS 실패(위험)"로 집계 → 제외하고 회귀 테스트 추가.
- **안정성**: Wi-Fi처럼 무차별 모드가 안 되는 인터페이스에서 캡처가 실패하던 문제 → 자동으로 일반 모드로 재시도. 종료 시 스레드 join + DB 닫기(테스트 추가). 도메인 이름 사전 상한(2만). 확장 규칙 내부 예외가 조용히 삼켜지던 문제를 테스트로 드러냄(`__slots__` 누락 → 수정).
- **메모리**: 테스트 서버 RSS 167MB(시작) → 189MB(약 31분 캡처 후). 24시간 연속 실행은 미측정.
- **정정**: 1단계 분석 17번(프루닝이 매 배치마다 COUNT)은 사실이 아니었음. 이미 5,000건마다 정리하고 있어 변경하지 않음.
